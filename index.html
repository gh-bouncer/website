How it works GitHub

Drive-by pull requests pay for their own review.

Pull requests from outside your team wait at the door until their author runs a thorough AI review, in their fork, on their own API key, against your rules. You only see the ones that pass.

$ gh extension install gh-bouncer/gh-bouncer
$ gh bouncer init  # opens a PR that installs it

Free for maintainers. No server, no account. It runs in GitHub Actions.

How a pull request gets in

  1. Someone outside your team opens a pull request

    The bouncer holds it as a draft and leaves one comment: the command to run. Members, collaborators and past contributors walk straight in.

  2. They run gh bouncer

    The review runs in their fork, on their key. It reads every changed file in full, checks callers and tests, searches your issues for duplicates and past declines, and judges each of your rules with file and line evidence.

  3. The bouncer checks the signature

    A passing pull request reaches you with the review attached. A failing one is closed with the reasons, and the author can push fixes and try again.

Your door, your rules

Everything the reviewer judges lives in .bouncer.yml in your repository. Contributors can't see a softer version or change it from their side.

Write your rules in plain language. The guidance field, where you say what the project is for and what you never accept, does the most to sharpen verdicts.

A hard rule only closes a pull request when the reviewer is confident and the evidence it cites checks out against the real files. Anything else is passed along as a note.

review:
  model: claude-opus-5-5
  effort: high
gate:
  deadline_hours: 48
  close_on_fail: true
checks:
  require_linked_issue: true
guidance: |
  Zero dependencies, one public function.
  No cosmetic-only changes.
rules:
  - id: not-duplicate
    hard: true
    description: Not already fixed, and not
      something we declined before.
  - id: has-tests
    hard: false
    description: Behavior changes come with tests.

A pass can't be faked

  • Signed by GitHub

    Every review is signed by GitHub as the output of the bouncer's own workflow. Edit the workflow, or run it anywhere but GitHub's runners, and the signature no longer matches.

  • Your settings, not theirs

    The model, effort and rules come from your repository. The contributor supplies a key and nothing else.

  • First review counts

    Every review of the same commit is recorded, and only the earliest one counts. Re-rolling until the model says yes doesn't work.

  • Untrusted text stays data

    Instructions hidden in a pull request aimed at the reviewer are flagged and fail it. The final call is made in code, from verified evidence.

Held at the door?

Run the command from the bouncer's comment. It sets up your fork, asks for your Anthropic API key once and keeps it as a secret in your fork, runs the review and reports back. After that, every push to your pull request is reviewed automatically.

$ gh extension install gh-bouncer/gh-bouncer
$ gh bouncer https://github.com/owner/repo/pull/123
