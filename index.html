gh bouncer
How it works Repo Config Action Extension

Outside pull requests are reviewed by the contributor's own AI, in their own GitHub Actions, before they ever reach you.

  • No account
  • No server
  • No bill
  • 100% free
$ gh extension install gh-bouncer/gh-bouncer

Then run gh bouncer init in your repository.

How a pull request gets in

1

Someone outside your team opens a pull request

The bouncer holds it as a draft and leaves one comment: the command to run. Your team walks straight in.

github.com/acme/widget/pull/412

Add retry to fetch() #412

Draftdrive-by-dev wants to merge 1 commit into mainbouncer:pending
D
drive-by-dev commented

This PR improves robustness and overall code quality ✨

⦿github-actions added the bouncer:pending label and marked this as a draft
✋
github-actions bot commented

🚪 Bouncer review required

Thanks for the pull request! Before a maintainer looks at it, this project asks outside contributors to run an AI review of their change. It runs in your fork's GitHub Actions, on your own Anthropic API key, so maintainers pay nothing.

gh extension install gh-bouncer/gh-bouncer
gh bouncer https://github.com/acme/widget/pull/412

Deadline: Sun Oct 11, 12:00 UTC · 3 review attempts left

2

They run gh bouncer

One command sets up their fork, stores their API key as a secret there, and starts the review.

drive-by-dev ~ zsh

        

      


      

        

          3
          
Their GitHub Actions do the work

          
The review runs in their fork, on their key, against your rules. It reads the code, checks for duplicates, and GitHub signs the result.

A pass can't be faked

    
    
      
  • Signed by GitHub
    Each review is signed as the output of bouncer's own workflow. Edit it and the signature breaks.
    • 
      
  • Your settings
    Model, effort and rules come from your repository. The contributor only brings a key.
    • 
      
  • First review counts
    Only the earliest review of a commit counts. No re-rolling for a yes.
    • 
      
  • Injection fails
    Instructions aimed at the reviewer fail the pull request. The verdict is made in code.
    • 
    

  


  

    

      
Repo Config

      
Everything lives in .bouncer.yml in your repository. Set it up here and copy the file. gh bouncer init starts you with these defaults, and contributors can't change any of it.

      

        
        
      

        


          

            

              

                
Review agent 

                
The model that reviews pull requests and how much work it does. Runs on the contributor's API key.

              

              
            

            

              

                Review agent
            

              
              
            

            

              Effort
              

                
                
                
                
                
              

              
Higher effort reads more of your code and costs the contributor more.

            

            

              
              
              
Tool calls before the agent must decide. Follows effort unless you change it.

            

              

            

          


          

            

              

                
Gate 

                
Deadlines, closing and exemptions. Label a pull request bouncer:skip to exempt it by hand.

              

              
            

            

              

                Gate
            

              
              
              
Pull requests without a review by then are closed.

            

            

              
              
              
Reviews allowed per pull request before it is closed for good.

            

            

              
              
              
When off, failed pull requests are labeled bouncer:fail and left open.

            

            

              
              
80%

              
A broken required rule fails the pull request only when the agent is at least this confident.

            

            

              
              
              
New commits pushed after a pass need a new review.

            

            

              
              
              
Owners, members and collaborators.
